1. Policy Kya Hai? (Simple Concept)

Architecture ka Flow Samajh Lein (Interview ke liye)
Jab aap se pucha jaye ke ye kaam kaise kar raha hai:
Client Request: User HR.Identity.API ko username/password bhejta hai.
Token Issuance: Identity API usey ek JWT Token deti hai jisme UserRole: Admin ka claim hota hai.
Gateway Entry: User ab Gateway ke raste /payroll access karne ki koshish karta hai aur sath Token bhejta hai.
Policy Check: Gateway (Ocelot) pehle token verify karta hai, phir dekhta hai ke aapne ocelot.json mein UserRole: Admin ki condition lagayi hui hai.
Forwarding: Agar Role match kar jaye, to Gateway request ko HR.Payroll.API tak bhej deta hai.

hr-gateway mein ocelot.json ke andar humne RouteClaimsRequirement lagayi hai jo JWT token se UserRole check karti hai. Ye Policy Enforcement hai jo ensure karti hai ke sirf 
authorized users hi sensitive services (jaise Payroll) tak pohnchein.

Maine HR system ko Microservices mein divide kiya hai jahan har service ka apna database hai. Ocelot API Gateway central entry point hai jo JWT-based Policies ke zariye security 
handle karta hai. Saara infrastructure Docker Compose par containerized hai, jo scaling aur deployment ko asaan banata hai.

points to remember
==================
microservices k concept me api hit phly api gateway prr jaegi ya phirr Identity Api prr jaegi?
Microservices architecture mein standard flow ke mutabiq, API hit pehly API Gateway par jati hai. API Gateway aapke system ka "Single Entry Point" hota hai jo client aur backend 
microservices ke darmiyan ek gatekeeper ka kaam karta hai. 

Request ka safar aam tor par kuch is tarah hota hai:
API Gateway (First Stop): Client (web ya mobile app) se aane wali har request pehly Gateway par land karti hai. Gateway decide karta hai ke request ko kis service (e.g., Order 
service, Product service) ki taraf bhejna hai.
Authentication/Identity Check: Gateway khud hi request ko validate karta hai. Agar authentication zaroori ho, to Gateway background mein Identity API (Identity Provider) se rabta 
karke token verify karta hai. Baaz dafa Gateway khud hi token validation kar leta hai bina har bar Identity API ko hit kiye.
Routing to Microservice: Jab request verify ho jati hai, tab Gateway usay sahi backend microservice tak pohanchata hai.

Docker Spacing/Slow issue
==============================
Bhai, aapka laptop kafi taqatwar hai (12 CPUs aur 7.4GB allocated RAM), is liye abhi toh aapka system sukoon mein hai. Lekin agar aapki hr-app zyada 
space (RAM ya CPU) consume karne lagay, toh ye 3 cheezein ho sakti hain:
1. Application "Lag" ya Slow ho jayegi
Agar RAM full hone ke qareeb pohnchi, toh aapka Angular frontend load hone mein time lega aur backend requests "Time out" hona shuru ho jayengi. User 
ko lagega ke app hang ho gayi hai.
2. OOM Kill (Out of Memory)
Docker boht sakht "Security Guard" hai. Agar koi container (maslan hr-payroll) itni zyada RAM khane lagay ke laptop ke liye khatra ban jaye, toh 
Docker us container ko foran kill (band) kar dega.
Aapko Docker Desktop mein wo container Red nazar aayega aur error likha hoga: "Exited with code 137".
3. System Hang (Laptop Heat-up)
Kyunke aapke paas 12 CPUs hain, CPU ka masla itni jaldi nahi aayega. Lekin agar CPU usage 90% se upar gayi, toh laptop ka fan tez chalne lagega aur 
poora Windows slow ho jayega.
Is se bachne ka "Pro" tareeqa (Docker Limits):
Aap apni docker-compose.yml mein har service ke liye limit set kar sakte hain taake koi ek service poore laptop ka sukoon tabah na kare:

services:
  hr-payroll:
    deploy:
      resources:
        limits:
          cpus: '0.50'     # Sirf aadha CPU use kar sakay
          memory: 512M     # 512MB se zyada RAM na lay

Docker vs .NET Aspire (Farq Kya Hai?)
Docker Desktop: Sirf containers ko chalata hai. Yeh "infrastructure" level ki cheez hai.
NET Aspire: Aapko code ke andar se in containers ko manage karne ki taqat deta hai.

Aspire Kyun "Cool" Hai? (HR Project ke liye)
Automated Orchestration: Aapko manually har project ki Dockerfile ya complex Compose file nahi likhni parti. C# code mein hi bata dete hain ke 
"Project A" ko "Project B" se baat karni hai.
Built-in Telemetry: Aapki image mein itne saare services hain. Aspire aapko ek Developer Dashboard deta hai jahan aap dekh sakte hain ke Gateway se 
request Payroll tak gayi to kitni der lagi (Tracing).
Local Development: Jab aap Visual Studio mein "F5" dabayenge, to Aspire saare containers ko sahi sequence mein khud start kar dega.

.NET Aspire Orchestrator Kaise Add Karein?
Aap apne mojooda HR project mein niche diye gaye asaan steps se Aspire add kar sakte hain:
Workload Install Karein: Sabse pehle apne terminal mein ye command chalayein:

OpenTelemetry (OTel) aik open-source standard hai jo aapki application se Logs, Metrics, aur Traces (inhein "Signals" kehte hain) nikalne (collect

Humne ise kyun add kiya hai? (Asli Maqsad)
Iske 3 baray faide hain jo aapne interviewer ko batane hain:

Distributed Tracing (Sabse Imp): Microservices mein masla ye hota hai ke jab request Gateway se Payroll API aur phir Database tak jati hai, to beech 
mein kahan rukawat (bottleneck) aayi, ye pata nahi chalta. OpenTelemetry poori request ka aik "X-ray" nikal kar dikhati hai ke kis step ne kitne 
millisecond liye.

No Vendor Lock-in: Kal ko agar aap Aspire se shift ho kar Azure Monitor, Jaeger, ya Prometheus par jana chahen, to aapko code change nahi karna 
parega. OTel sab ke sath "baat" kar sakta hai.

Automatic Observability: Aapko har function mein Log.Information likhne ki zaroorat nahi. OTel khud hi HTTP requests, Database queries, aur Exception 
handling ko track kar leta hai.

HR.Shared.Library mein kaam karne ka maqsad ye hai ke har service (Employee, Payroll, Identity) khud se Key Vault se connect na kare, balkay is shared logic ko use 
kare.Agla step: Ek Helper class banate hain.HR.Shared.Library ke Helpers folder mein ek nayi file banayein, let's say KeyVaultHelper.cs, aur ye basic structure 
wahan paste karein:

using Azure.Identity;
using Azure.Security.KeyVault.Secrets;

namespace HR.Shared.Library.Helpers
{
    public interface IKeyVaultHelper
	{
		Task<string> GetSecretValueAsync(string secretName);
	}
	public class KeyVaultHelper : IKeyVaultHelper
	{
		private readonly SecretClient _client;

		public KeyVaultHelper(string vaultUri)
		{
			// DefaultAzureCredential local development (VS/CLI) 
			// aur Azure (Managed Identity) dono ke liye kaam karta hai.
			_client = new SecretClient(new Uri(vaultUri), new DefaultAzureCredential());
		}

		public async Task<string> GetSecretValueAsync(string secretName)
		{
			var secret = await _client.GetSecretAsync(secretName);
			return secret.Value.Value;
		}
	}
}

==========================================
Sagga Design Pattern
==========================================
Distributed Transaction: Jab kaam 3 databases mein hona ho aur ek fail ho jaye, toh baaki 2 ko "undo" kaise karein?
Compensating Transaction: Ye "Rollback" ka naya naam hai. Agar Step 3 fail hua, toh Step 2 aur Step 1 ko "Reverse" karne wala code chalana.
State Machine: Ek central manager jo yaad rakhta hai ke: "Employee table mein entry ho gayi? Done. Payroll mein ho gayi? Fail! Ab pehle wali entry 
delete karo."
